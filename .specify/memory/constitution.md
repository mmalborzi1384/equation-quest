# Equation Quest Constitution

## Core principles
1. **Teach before rewarding.** Every puzzle requires an observable mathematical action, explanatory feedback and verification; avoid answer guessing and punishment loops.
2. **Functional multi-page product.** Independent route/page/feature ownership; each visible control has meaningful behavior, including on mobile and keyboard. No mock-only release.
3. **Pure mathematical core.** Equation generation, checking, substitution and feedback are deterministic/testable without React or Three.js; game calls domain APIs, not vice versa.
4. **Accessible Persian-first interface.** RTL text, explicit LTR mathematics, Vazirmatn, visible focus, reduced motion and legible contrast. No scroll-controlled gameplay.
5. **Static and resilient.** No required account or backend; GitHub Pages with HashRouter/base path, versioned local persistence and recoverable save data.
6. **Intentional craft.** The balance/bridge motif ties copy, shape and motion to lessons. Use glass selectively. Read anti-slop rules during work; never ship unverified claims or dead controls.
7. **Evidence and scope honesty.** Spec → clarify → plan → checklist → tasks → analyze → implement → converge per feature; tests precede completion claims. Preserve research and decisions in repo.

## Constraints
React, TypeScript strict, Vite, React Router, Three/R3F/Drei, GSAP, Zustand persist, CSS Modules/tokens, KaTeX, Vitest/RTL/Playwright. Web reference adapts Expo carousel behavior only; no React Native dependency. 8 levels across 4 islands, equality/unknown/inverse/solve progression; exact signed and rational `ax+b=c` equations (`a≠0`) are required, with an independent fraction lesson and practice, fraction objectives in levels 06–08, and pre-publication curriculum/Persian-content review. Desktop and mobile controls; performance presets. No full app implementation before user sign-off.

## Governance
User's latest explicit instruction supersedes project documents. Architectural deviations require a dated entry in `docs/DECISIONS.md` with alternatives, rationale, impacts and owner approval when necessary. Feature gate: acceptance criteria met, maths reviewed, keyboard/touch checked, reduced motion checked, tests passing and anti-slop delivery gate recorded. Update memory/status after each task.
